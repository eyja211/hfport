# hfport

[简体中文](README.md) | [English](README.en.md) | **日本語**

**Hero Fighter キャラクター移植ツール**は、互換性のある Hero Fighter
本体や mod の間で、プレイヤーが選択できるキャラクターを移植するための
ツールです。キャラクターの依存データを解析し、リソース名の衝突を処理し、
移植先に必要な登録処理を追加したうえで、元のファイルを上書きせずに新しい
EXE を生成します。

> このリポジトリで公開しているのはツールのソースコードのみです。
> Hero Fighter の EXE、SWF、ゲーム素材、FFDec、移植済みゲーム本体は
> 含まれていません。

## 移植対象

- キャラクターの SPT データと LMI テクスチャ
- `globalDat` から参照される攻撃データと Pt テンプレート
- キャラクターが使用する item アクショングループ、飛び道具、テクスチャの独立コピー
- 移植先に存在しないキャラクター用サウンド
- キャラクター一覧と VS 選択画面への登録
- 移植先の既存キャラクターを利用した経験値データの関連付け

移植ごとに、移植元ファイル名から短い名前空間を生成します。同じ名前空間が
移植先ですでに使われている場合、hfport は次の番号を自動的に割り当てます。
キャラクターが参照する item グループは、元と移植先の `int1` が同じでも
必ず新しいインデックスへコピーされるため、移植先 mod で変更された同番号の
item を誤って使用することはありません。

## 対応範囲

hfport は Hero Fighter シリーズと、互換性のある Flash データ構造を採用した
派生 mod を対象としています。特定の mod 名や単一のバージョン番号に固定された
ツールではありません。

現在の実装では、入力ファイルが SWF を内包した Windows Flash projector であり、
一般的な Hero Fighter のデータ構造と登録処理を保持している必要があります。

- `globalDat`、`itemSpt`、`itemLmi` を含む `Data.Global_*` バイナリ素材
- `Data.BgInfoFile` のデータ読み込み処理
- `Data.Global` のキャラクター登録と経験値初期化
- `Web_misc.SelectCharPanel` のキャラクター選択リスト
- `Page.CharList` のキャラクター一覧ページ処理

バージョンや大幅に改造された mod によっては、これらの構造が変更されている
場合があります。必ず移植先ファイルのコピーを使用し、ツールの静的検証に
通したうえで、ゲーム内で動作確認してください。すべての Hero Fighter
バージョンや mod との互換性を保証するものではありません。

## 動作環境

- Windows
- Python 3.8 以降（標準ライブラリのみ使用）
- Java
- [JPEXS Free Flash Decompiler（FFDec）](https://github.com/jindrapetrik/jpexs-decompiler)
  （ツールが必要とする一部の登録コードを抽出するために使用）

`ffdec.jar` を `FFDec/ffdec.jar` に配置するか、設定ファイルでパスを指定して
ください。FFDec とゲームファイルは Git リポジトリの外で管理してください。
付属の `.gitignore` は一般的なローカル構成を除外するよう設定されています。

## クイックスタート

1. このリポジトリをクローンします。
2. `FFDec/ffdec.jar` を用意するか、絶対パスを確認します。
3. ローカルの作業フォルダに、移植元と移植先の EXE のコピーを用意します。
4. `移植工具.bat` をダブルクリックするか、次のコマンドを実行します。

   ```powershell
   python -m hfport.cli
   ```

5. 移植元、移植先、移植するキャラクターを選択します。hfport で拡張済みの
   バージョンも、再び移植元または移植先として使用できます。
6. 静的検証の結果を確認し、ゲーム内で動作テストを行います。

生成ファイルは既定で `output/` に出力されます。選択した移植元 EXE や
移植先 EXE を上書きすることはありません。

## 設定ファイルでの実行

`examples/port-config.example.json` を参考にローカル設定を作成し、サンプルの
パスを実際のパスへ置き換えてから実行します。

```powershell
python -m hfport.cli --config path\to\port-config.json
```

移植を実行せず、移植元で選択可能なキャラクターだけを表示する場合：

```powershell
python -m hfport.cli --list "C:\path\to\source-build.exe"
```

## 検証

ビルド後、hfport は生成された projector/SWF の構造、ABC の往復一致、
追加素材、主要データ参照、キャラクター登録文字列を検証します。静的検証の
通過は必要条件ですが、最終的にはゲーム内で次の項目を確認してください。

- ゲームの起動とバトルの読み込み
- キャラクター一覧と VS 選択画面
- モーション、攻撃、飛び道具
- item の挙動、テクスチャ、サウンド
- 経験値の関連付け
- 移植先に元から存在するキャラクターの動作

`hfport/tests/` の一部の統合テストには、ローカルのゲームファイルと FFDec が
必要です。これらは公開リポジトリには含まれていません。どの環境でも次の
ソースコード検査を実行できます。

```powershell
python -m compileall hfport
python -m hfport.cli --help
```

FFDec から抽出した登録情報は、入力 EXE 全体の SHA-256 ごとに別のディレクトリへ
キャッシュされます。別バージョンへ切り替えた際に、以前の `pow`、経験値の
関連付け、キャラクター選択データを誤って再利用することはありません。

## リポジトリ構成

```text
hfport/                 解析、移植、登録パッチ、検証、CLI
hfport/tests/           単体テストとローカルゲームファイルを使う統合テスト
examples/               機密情報を含まない設定例
移植工具.bat             Windows 用ダブルクリック起動ファイル
work/                   自動生成される中間ファイル（Git 対象外）
output/                 自動生成される移植結果と設定（Git 対象外）
```

## 安全上の注意

- 必ず移植元と移植先ファイルのコピーを使用してください。
- 配布権限がない限り、ゲームの EXE、SWF、抽出素材、移植済みゲーム本体を
  公開しないでください。
- オンライン対戦では、参加者全員が完全に同じ生成済みゲームを使用する必要があります。
- 移植元 mod の AS3 エンジンコードで実装された特殊機能はデータ移植の対象外です。
  移植後は移植先のエンジン処理に従います。
